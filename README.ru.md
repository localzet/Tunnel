# Localzet Tunnel

[English documentation](README.md)

Tunnel — небольшой TCP-брокер сообщений для PHP-приложений на Localzet Server. Он поддерживает публикацию и подписку на каналы, а также очереди в памяти.

## Состояние и совместимость

## Совместимость

Версия 3 предназначена для Localzet Server 7 и PHP 8.1 или новее. Предыдущая ветка 2.x рассчитана на Server 4 и несовместима с Server 7. Перед переносом приложения проверьте изменения API и доставки сообщений.

Сообщения и очереди хранятся в памяти брокера. Очереди не сохраняются на диск, подтверждения доставки и повторной отправки нет. Для одного пространства каналов запускайте один процесс брокера: независимые брокеры не делят подписки и состояние очередей.

Десериализация PHP-объектов по умолчанию отключена. Чтобы сохранить объектные данные в доверенной изолированной сети, включите режим на обеих сторонах: передайте `allowObjectSerialization: true` третьим аргументом конструктора `Server` и вызовите `Client::allowObjectSerialization()` до подключения. Не включайте десериализацию объектов для недоверенных узлов.

В Tunnel нет аутентификации клиентов и шифрования. Привяжите брокер к приватному интерфейсу и ограничьте сетевой доступ. Не открывайте listener напрямую в публичный Интернет.

## Зависимости

- `php`: `>=8.1`
- `localzet/server`: `^7.0`

## Установка

```sh
composer require localzet/tunnel:^3.0
```

Для Server 7 используйте ветку релизов 3.x. Релизы 2.x предназначены для приложений на Server 4.

## Быстрый старт

Запустите брокер на приватном хосте:

```php
<?php

require __DIR__ . '/vendor/autoload.php';

new \localzet\Tunnel\Server('frame://127.0.0.1:9010');
\localzet\Server::runAll();
```

Подключите клиент Tunnel из worker-процесса Localzet Server и подпишитесь на канал:

```php
use localzet\Tunnel\Client;

Client::connect('frame://127.0.0.1:9010');
Client::on('orders', static function (mixed $order): void {
    // Обработайте опубликованное сообщение.
});
Client::publish('orders', ['id' => 42]);
```

`Client` использует асинхронное соединение и таймеры Localzet Server. Вызывайте его из приложения, работающего в event loop Server. Для обычного CLI-процесса используйте клиент с поддержкой протокола или запускайте интеграцию через Server: синхронного standalone API в `Client` нет.

Брокер принимает JSON и прежний формат PHP serialization. Для новых клиентов используйте скаляры и массивы без PHP-объектов. Передача объектов требует явного opt-in для доверенной сети.

## Поведение и ограничения

- `publish` отправляет событие всем подписчикам, `publishLoop` — одному подписчику по очереди.
- `watch` вместе с `reserve` получает элементы очереди из памяти. Перезапуск процесса удаляет очередь.
- Нет аутентификации, TLS, постоянного хранения, подтверждения доставки, повтора, воспроизведения или репликации между брокерами.
- Оставляйте брокер в доверенной сети. Протокол listener не проверяет права клиентов и каналов.

## Проверки разработки

```sh
composer validate --strict
composer install
composer run check
composer audit
```

Интеграционный тест запускает локальный брокер и проверяет публикацию, очередь, некорректный ввод и отключённую десериализацию объектов. Он не подтверждает готовность production-развёртывания и не проверяет работу между хостами.

[Исторические примеры](docs/legacy-readme.md) нужно сверять с текущим API.
